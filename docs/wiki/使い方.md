## 0. 設計の読み方

| 軸 | 利用者が書くもの |
|----|------------------|
| **個体** | `(instance …)` と `(arg …)` — スロットだけ変える |
| **種族** | `(wiki-site)` など **1 フォーム**（中の pkg 列は書かない） |
| **運用** | 書かない。言語（agent）が cmd・host ネット量産を拒否 |

**前提:** ファイルは常に「一つの jail 個体」の計画。`(host)/(in-jail)` ブロックは無い。

**展開:** hostname 埋め込み・dataset 導出・種族の pkg は言語側。利用側 sed は使わない。

---

## 1. 構文一覧

### 個体・ベース

| 構文 | 意味 |
|------|------|
| `(instance #:name "…" #:hostname "…" #:data-host "…" #:ip "…" #:dataset "…")` | 個体スロット（省略可のキーあり） |
| `(arg hostname)` / `(arg x "default")` | 引数（`--arg` またはデフォルトで埋める） |
| `(name "…")` | Jail 名（`instance #:name` と同等に使える） |
| `(from zfs "pool/ds@snap")` | ZFS スナップからクローン |
| `(from thin freebsd-14.3)` | Thin jail（実行は TODO が多い） |
| `(option network vnet-default)` | ネットモード（量産向け。`host` は agent 不可） |
| `(option dataset "…")` | dataset **明示**（通常は name から導出されるので不要） |

### 種族

| 構文 | 意味 |
|------|------|
| `(wiki-site)` | DokuWiki+Caddy 種族。hostname/data-host は `{{hostname}}` 等でスロット参照 |
| `(wiki-site #:hostname "…" #:data-host "…" #:forbid-install? #t)` | スロットをキーワードで渡す形も可（単一ソースを壊さないこと） |

### 手順語彙（種族を使わないとき）

| 構文 | 意味 |
|------|------|
| `(pkg "nginx")` | パッケージ |
| `(sysrc "k" "v")` | rc.conf |
| `(copy src dst)` | ファイル投入 |
| `(service nginx start)` | サービス |
| `(volume host-path jail-path)` | nullfs 等 |
| `(pw-group …)` `(pw-user …)` `(smb-password …)` | Samba 向け |
| `(template-subst path old new)` | プレースホルダ置換 |

### 常用しない（運用）

| 構文 | 意味 |
|------|------|
| `(cmd …)` / `(human-cmd …)` | agent **不可**。人間は `--human --allow-cmd` のみ |

---

## 2. フェーズ

| phase | 内容 |
|-------|------|
| `build`（既定） | 作成・投入 |
| `start` / `stop` | 起動 / 停止 |
| `destroy` | 破棄 |

## 3. 完成例

### 3.1 DokuWiki（推奨パターン）

`examples/dokuwiki-caddy.rkt`:

```racket
#lang makejail

(from zfs "zroot/jails/base@clean")
(option network vnet-default)

(instance
 #:name "dokuwiki-caddy"
 #:hostname "{{hostname}}"
 #:data-host "{{data-host}}")

(arg hostname)
(arg data-host)

(wiki-site)
```

### 3.2 nginx

`examples/nginx.rkt`:

```racket
#lang makejail

(from zfs "zroot/jails/base@clean")
(option network vnet-default)

(instance #:name "web-nginx")

(pkg "nginx")
(sysrc "nginx_enable" "YES")
(copy "templates/nginx.conf" "/usr/local/etc/nginx/nginx.conf")
(service nginx start)
```

### 3.3 Samba

`examples/samba.rkt` — `(instance …)` + `(arg samba-password)` + `pw-*` / `smb-password`（cmd なし）。  
詳細は [examples-freebsd15](examples-freebsd15)。

## 4. CLI（運用）

### 4.1 インストール

```bash
cd /path/to/my-makejail-lop
raco pkg install --link .
# 以後: raco makejail <サブコマンド> FILE [オプション…]
```

引数の順序は自由です（`--arg` や `--apply` は FILE の前後どちらでも可）。

---

### 4.2 サブコマンド一覧

形式:

```text
raco makejail <plan|check|build|start|stop|destroy> FILE [flags…]
```

| サブコマンド | 何をするか | 既定の dry-run | 典型用途 |
|-------------|------------|----------------|----------|
| **`plan`** | 計画を読み、**効果列を表示**するだけ | **常に dry-run**（`--apply` しても実行しない） | レビュー・PR・「何が起きるか」の共有 |
| **`check`** | `plan` と同じ（効果列表示・常に dry-run） | **常に dry-run** | エージェント成果物の合格判定、CI |
| **`build`** | フェーズ `build`（または `--phase`）で作成・pkg 投入など | **dry-run 既定**。実変更は `--apply` | 日常の構築 |
| **`start`** | フェーズ `start`（jail 起動系の効果） | dry-run 既定 / `--apply` で実行 | 再起動後など |
| **`stop`** | フェーズ `stop` | 同上 | メンテ前の停止 |
| **`destroy`** | フェーズ `destroy`（停止 + dataset 破棄など） | dry-run 既定 / `--apply` で実行 | 個体の廃棄（**破壊的**） |

共通の流れ（どのサブコマンドでも）:

1. `FILE` を `#lang makejail` として読み、`current-plan` を得る  
2. `--arg` で個体スロットを束縛  
3. **agent/human の受理検査**（`plan-validate!`）  
4. 効果列を組み立てて表示  
5. dry-run ならここで終了。`--apply` かつ FreeBSD なら効果を順に実行  

失敗時に **自動ロールバックはしません**。`--apply` 前に必ず `plan` / `check` / `build --dry-run` で効果列を確認してください。

---

### 4.3 `--dry-run` と `--apply`

| フラグ | 意味 |
|--------|------|
| **（フラグなし）** | **dry-run 相当が既定**（ホストを変更しない） |
| **`--dry-run`** | 効果列の表示のみ。OS・ZFS・jail に手を入れない。Linux 開発機でも安全 |
| **`--apply`** | 効果を **本当に実行**する。**FreeBSD ホスト上**でのみ成功する（非 FreeBSD はエラー終了）。`MAKEJAIL_FORCE_FREEBSD=1` は開発用の強制スイッチ |

**重要（実装どおり）:**

- `plan` と `check` は **常に dry-run** です。`--apply` を付けても実実行しません。  
- 実実行したいのは主に **`build` / `start` / `stop` / `destroy` + `--apply`** です。  
- `destroy --apply` は jail 停止と ZFS destroy 等を含み得ます。dry-run で効果列を読んでから実行してください。

```bash
# 安全: 効果列だけ見る（推奨の第一歩）
raco makejail plan examples/dokuwiki-caddy.rkt \
  --arg hostname=wiki.example.com \
  --arg data-host=/zroot/dokuwiki-data

raco makejail check examples/dokuwiki-caddy.rkt \
  --arg hostname=wiki.example.com \
  --arg data-host=/zroot/dokuwiki-data

# build も既定は dry-run（明示してもよい）
raco makejail build examples/dokuwiki-caddy.rkt --dry-run \
  --arg hostname=wiki.example.com \
  --arg data-host=/zroot/dokuwiki-data

# FreeBSD 上だけで実構築
raco makejail build examples/dokuwiki-caddy.rkt --apply \
  --arg hostname=wiki.example.com \
  --arg data-host=/zroot/dokuwiki-data
```

dry-run の出力例（イメージ）:

```text
==> makejail phase=build dry-run=#t jail=dokuwiki-caddy
• zfs-clone …
• jail-create-path …
• pkg-install …
• template-subst … {{HOSTNAME}} → wiki.example.com
• volume …
• service …
[dry-run] no host changes.
```

`--apply` 成功時は同じ効果列のあとに、各ステップがホスト上で実行されます。途中失敗しても **巻き戻し無し** — ログと jail / dataset を手で確認します。

### 4.4 ライフサイクル運用（推奨手順）

#### A. 新規個体を立てる

```bash
# 1) ホスト準備（ZFS スナップ・データ用ディレクトリ）
sudo mkdir -p /zroot/dokuwiki-data
# zroot/jails/base@clean が存在すること

# 2) 計画の確認（何度でも）
raco makejail check examples/dokuwiki-caddy.rkt \
  --arg hostname=wiki-03.example.com \
  --arg data-host=/zroot/dokuwiki-data

# 3) FreeBSD で適用
raco makejail build examples/dokuwiki-caddy.rkt --apply \
  --arg hostname=wiki-03.example.com \
  --arg data-host=/zroot/dokuwiki-data
```

#### B. 止める / また起動する

```bash
raco makejail stop  examples/dokuwiki-caddy.rkt --dry-run --arg hostname=… --arg data-host=…
raco makejail stop  examples/dokuwiki-caddy.rkt --apply  --arg hostname=… --arg data-host=…

raco makejail start examples/dokuwiki-caddy.rkt --dry-run --arg …
raco makejail start examples/dokuwiki-caddy.rkt --apply  --arg …
```

`start` / `stop` も **先に dry-run** で効果（`jail-start` / `jail-stop` 等）を確認してから `--apply` するのが安全です。

#### C. 個体を捨てる（destroy）

```bash
# 必ず dry-run で zfs-destroy 等が出ることを確認
raco makejail destroy examples/dokuwiki-caddy.rkt --dry-run \
  --arg hostname=wiki-03.example.com \
  --arg data-host=/zroot/dokuwiki-data

raco makejail destroy examples/dokuwiki-caddy.rkt --apply \
  --arg hostname=wiki-03.example.com \
  --arg data-host=/zroot/dokuwiki-data
```

- **volume のホスト側データ**（例: `/zroot/dokuwiki-data`）は、destroy の効果に含まれないことがあります。永続データを消すかどうかは運用で別判断してください。  
- dataset 名は通常 `zroot/jails/<name>`（name から導出）。dry-run の `zfs-destroy` 行で対象を確認します。

#### D. エージェント成果物の受け取り

```bash
# エージェントが書いた FILE を人間が検査（副作用なし）
raco makejail check path/to/agent-output.rkt \
  --arg hostname=… \
  --arg data-host=…
# 効果列に jexec-cmd が無く、network host が無いこと（P02）
# 問題なければ人間が build --apply
```

### 4.5 `--phase`（主に build 向け）

| 値 | 意味 |
|----|------|
| `build` | 既定。clone / create / pkg / 設定 / service など |
| `start` | 起動系（`start` サブコマンドと同等のフェーズ） |
| `stop` | 停止系 |
| `destroy` | 破棄系 |

```bash
# build サブコマンドで phase を明示（通常はサブコマンド start/stop/destroy を使う）
raco makejail build FILE --phase start --dry-run --arg …
```

`plan` / `check` は内部でフェーズ **build** の効果列を出します（常に dry-run）。

---

### 4.6 受理・権限フラグ

| フラグ | 既定 | 意味 |
|--------|------|------|
| `--agent` | **既定** | 厳しい受理。`(cmd)` 不可、`network host` 量産不可 |
| `--human` | オフ | 人間モード（それでも cmd には `--allow-cmd` が必要） |
| `--allow-cmd` | オフ | `(cmd)` / `(human-cmd)` を許可 |
| `--allow-host-net` | オフ | `(option network host)` を許可 |
| `--arg k=v` | なし | 個体スロット注入。**繰り返し可**。argv のどこでも可 |

```bash
# 量産・エージェント（推奨）
raco makejail check FILE --agent --arg hostname=… --arg data-host=…

# 例外的に host ネットや cmd を試す（人間・実験のみ）
raco makejail build FILE --human --allow-host-net --dry-run
raco makejail build FILE --human --allow-cmd --dry-run
```

必須 `(arg hostname)` などが未束縛のままだと、check/plan の段階でエラーになります。`--arg` か、環境変数 `MAKEJAIL_ARG_<名前>` を使います。

---

### 4.7 運用チェックリスト（短い）

| 場面 | コマンド |
|------|----------|
| 書いた・受け取った | `check` または `plan`（常に安全） |
| 適用前の最終確認 | `build --dry-run`（または start/stop/destroy の `--dry-run`） |
| 本番適用 | 対応サブコマンド + **`--apply`**（FreeBSD） |
| 廃棄 | `destroy --dry-run` → 効果確認 → `destroy --apply` |
| エージェント納品 | `check` で P02 合格 → 人間が `build --apply` |

Linux 上の開発では **check / plan / \* --dry-run までがすべて**です。`--apply` は FreeBSD 運用ホストで行います。

---

## 5. 注意（必読）

| 項目 | 内容 |
|------|------|
| 単一ソース | hostname を instance/arg と wiki-site リテラルで矛盾させない |
| dataset | 手書きと name の二重管理をしない（導出に任せる） |
| ネット | agent では `host` 不可。thin-vnet は [Issue #3](https://github.com/bluehive/my-makejail-lop/issues/3) |
| ZFS | `base@clean` がホストに必要 |
| pkg 版 | FreeBSD 15 想定の `php84` / `samba420` は環境で読み替え |
| パスワード | Samba は `--arg samba-password=` のみ |

エージェント契約: [P02](https://github.com/bluehive/my-makejail-lop/blob/main/docs/P02-agent-contract.md)
